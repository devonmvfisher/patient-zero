HORIZON (one definition, fixed here):
  link lag = time of the adopter's first use F minus time of the credited source use U (the row the cascade
  credits; most recent visible earlier use). A named link counts at horizon H iff lag <= H seconds.
  24 h = 86,400 s; 72 h = 259,200 s; 7 d = 604,800 s; none = no limit. Because U is the most recent qualifying
  use, no older use can qualify when U is too old, so the filter never changes who is credited: cells nest
  (24 h <= 72 h <= 7 d <= none) in the real count and in every shuffle. The same filter is applied to every
  shuffle, on that shuffle's own times.

STATISTIC: cross-page named links (credited source row on a different page from the adopter's first-use row),
  per token class and per horizon. Same-page links reported beside, no pass line.
CLASSES: the tracer's six classes: host, file, code, phrase, convention (the task's five) and command (1 token
  in the real data, kept as its own sixth row so the class cells still sum to the total). Convention kinds are

NULL: N3 order null, agent-day scope, 100 shuffles, one random.Random(20261003): the same permutations as
  checks.json, E7, E7b and E7c (reorder's random draws do not depend on the token set).

CELL READING (the PREREG-v2 V rule, applied per cell, descriptive only):
  "above" if z >= 3 and at most 1 of 100 shuffles >= observed; "below" if z <= -3 and at most 1 of 100 shuffles
  <= observed; otherwise "at chance". z is None (no spread) reads "at chance (no spread)".

BREADTH READING per horizon (descriptive only; primary column = none):
  L = the class with the largest null-mean cross-page count in the "none" column (predicted: phrase); kept the
  same at every horizon. REST = all other classes pooled (sum per shuffle). R = total observed / total null mean.
  z_null = (obs_rest - mean_rest) / sd_rest. z_prop = (obs_rest - R * mean_rest) / sd_rest (how far REST is from
  a shortfall proportional to the total's).
  Evaluated in this order, first match wins (z None counts as 0):
    1 REST above chance        : z_null >= 2
    2 REST carries more        : z_prop <= -2
    3 broad                    : z_null <= -2 and |z_prop| < 2
    4 partly broad             : z_null <= -2 and z_prop >= 2    (REST below chance, but less than proportional)
    5 driven by L              : z_prop >= 2                      (REST at chance, and away from proportional)
    6 undetermined (low power) : otherwise (|z_null| < 2 and |z_prop| < 2)
  Also a drop-one table: the total minus each class in turn, with the V reading.

CONTROLS per horizon (random rows: no structure, so an unbiased statistic gives |z| < 2):
  C1 (primary, E7c-style): 40 tokens x 10 distinct agent rows, rng random.Random(20261031), rng.sample over agent
     rows in load order (exactly E7c "random"). Expected to reproduce E7c at "none": 29 vs 26.08, sd 3.401, z 0.86.
  C2 (secondary, new, chosen now): 400 tokens x 10 agent rows, rng random.Random(20261041), same sampler.
  A horizon is CALIBRATED only if C1 and C2 both give |z| < 2 on cross-page links (z None counts as a pass
  only when the control's observed equals its null mean; otherwise a fail). Any fail marks that horizon
  "uncalibrated" and its cells are reported with that mark. Known cost: with two controls a horizon is marked
  uncalibrated by chance about 9% of the time (conservative direction).
  K (power, reported, no pass line on the grid): the 40 planted carry cascades of E7b/E7c (exp2 generator,
     rng 20261023, carry_p 1.0, q 0.35, cap 40, 72 h generator horizon). Cross-page z per horizon; z >= 3 =
     "powered at this horizon". A horizon without power cannot call any cell "at chance" evidence of absence.
